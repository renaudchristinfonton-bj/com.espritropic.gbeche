⚙️ LES CAS D'UTILISATION STRICTS (De A à Z)

Voici ce que ton développeur doit coder, action par action.

UC 1 : Authentification et Ouverture (Le sas de sécurité)





Déclencheur : L'utilisateur ouvre l'application.



Exécution : L'application affiche un écran flouté (Glassmorphism). La librairie expo-local-authentication fait appel au système natif (iOS/Android) pour demander FaceID/Empreinte.



Résultat : Si échec ou annulation, fallback sur un pavé numérique pour le Code PIN. Si succès, décryptage de l'accès à WatermelonDB et affichage du Dashboard.

UC 2 : Création de la Hiérarchie (Guerre -> Bataille -> Adversaire)





Déclencheur : Clic sur le bouton flottant géant (FAB) "+".



Exécution : 1. L'utilisateur sélectionne un domaine (Guerre) existant ou crée un nouveau (choix d'icône et de couleur néon). 2. Il nomme l'Objectif (Bataille) et définit une Deadline (Date de fin). 3. Il découpe en Tâches (Adversaires). Il choisit la récurrence via un sélecteur intelligent (ex: "Jours spécifiques" -> Checkbox pour Lundi, Jeudi).



Enregistrement : WatermelonDB crée les entrées. Des triggers internes génèrent immédiatement toutes les instances futures des "Adversaires" dans la table du calendrier pour les 3 prochains mois.

UC 3 : Le "Flicage" Actif (Tracking des trous dans l'emploi du temps)





Déclencheur : Il est 15h00. Le calendrier local de 14h à 15h était vide.



Exécution : Une notification push locale programmée se déclenche : "1 heure s'est écoulée. Qu'as-tu fait ?".



Action UI : L'utilisateur clique sur la notification. Un Bottom Sheet (menu glissant du bas) s'ouvre avec des suggestions basées sur ses habitudes (ex: "Repos", "Scroll inutile", "Travail non prévu") et un champ texte.



Résultat : Le trou dans le calendrier est bouché. Les graphiques de productivité sont mis à jour en temps réel.

UC 4 : Réajustement Automatique d'un Adversaire (Tâche non faite)





Déclencheur : La fin de la journée approche (23h00) et des "Adversaires" prévus aujourd'hui ne sont pas cochés.



Exécution : L'application calcule les espaces vides dans le planning du lendemain.



Résultat : Une modale pop-up s'affiche : "Tu as perdu 2 batailles aujourd'hui. Je les ai reprogrammées demain à 10h et 14h. Accepter ?". Si oui, mise à jour des dates dans la DB. Si non, la tâche est marquée comme "Échec/Abandonnée" (impactant les graphiques de victoire).

UC 5 : Saisie via l'Agent IA Local (Le Chatbot)





Déclencheur : L'utilisateur n'a pas le temps de remplir des formulaires. Il ouvre l'onglet "Assistant".



Exécution : Il tape (ou dicte, via expo-speech vers texte) : "J'ai dépensé 2500 chez le coiffeur en cash, et rappelle-moi de lire 20 pages ce soir à 21h".



Logique : Une fonction Regex/NLP locale décompose la phrase.





Intent 1 : Finance -> Montant : 2500 -> Catégorie : Santé/Beauté (déduite de "coiffeur") -> Compte : Cash.



Intent 2 : Productivité -> Tâche : "Lire 20 pages" -> Heure : 21h00.



Validation : Le bot répond sous forme de cartes d'action : "Je m'apprête à faire ça : [Carte Dépense] + [Carte Tâche]. Valider ?".



Résultat : L'utilisateur clique sur "Valider tout". Écriture asynchrone dans WatermelonDB.

UC 6 : Portabilité des Données (Export/Import CSV)





Déclencheur : Clic sur "Sauvegarder mes données" dans les paramètres.



Exécution : Une fonction JavaScript parcourt les collections WatermelonDB, formate les données en chaînes séparées par des virgules (CSV), et utilise expo-file-system pour écrire le fichier dans le stockage local du téléphone.



Résultat : L'utilisateur peut partager ce fichier (expo-sharing) vers son mail, ou l'importer sur un autre appareil pour reconstruire la base de données.

🚀 L'ONBOARDING "GBECHE" : LE PARCOURS D'INITIATION

Le design sera en Glassmorphism sombre, avec des animations de particules qui réagissent au swipe de l'utilisateur.

Étape 1 : Le Manifeste (L'impact visuel)





Visuel : Une animation d'une boussole qui se transforme en épée (style néon).



Texte : "Le chaos s'arrête ici. GBECHE n'est pas un outil, c'est ton quartier général. Tes objectifs sont tes Guerres. Tes tâches sont tes Adversaires."



Action : Un seul bouton "Prendre le commandement".

Étape 2 : La Forteresse (Sécurité & Vie Privée)





Visuel : Un bouclier translucide qui pulse.



Texte : "Ce qui se passe dans GBECHE reste dans GBECHE. Pas de cloud, pas de serveurs, 100% hors-ligne. Tes données t'appartiennent."



Action : Déclenchement de la demande d'autorisation FaceID/Empreinte ou configuration du code PIN. Le junior doit utiliser expo-local-authentication ici. Si l'utilisateur refuse, on lui explique que sans protection, ses données financières sont à découvert.

Étape 3 : Le Recensement (Initialisation des Finances)





Visuel : Des cartes flottantes représentant les comptes (Momo, Wave, Cash).



Texte : "Quelles sont tes réserves ? Configure tes premiers portefeuilles."



Action : Un petit formulaire rapide. L'utilisateur saisit le solde actuel de ses comptes principaux.





Cas d'utilisation : L'utilisateur tape "50 000" pour MTN MOMO. Cela crée instantanément la première entrée dans la table accounts de WatermelonDB.

Étape 4 : Déclaration de Guerre (Premier Objectif)





Visuel : Une liste de domaines stylisés (Santé, Carrière, Spiritualité).



Texte : "Choisis ta première Guerre. Quel domaine de ta vie vas-tu conquérir aujourd'hui ?"



Action : L'utilisateur sélectionne un domaine. L'application lui demande alors son premier "Adversaire" (une tâche simple pour demain).



Psychologie : En lui faisant créer une tâche dès maintenant, on utilise le biais d'investissement. Il a déjà commencé, il ne voudra pas s'arrêter.

Étape 5 : Le Pacte de Discipline (Notifications)





Visuel : Une animation d'une horloge qui scanne le temps.



Texte : "Je serai ton ombre. Si tu dévies, je te ramènerai. Autorise-moi à te questionner sur ton temps."



Action : Demande de permission pour les Notifications. C'est ici qu'on programme les rappels horaires pour boucher les "trous" du planning.
